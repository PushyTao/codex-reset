# 邮箱配置指南

适用于 Codex Reset `1.1.x`，按当前 `/admin` 后台界面编写。服务商说明核对日期：2026-10-27。先完成 [Docker 部署](../README.md)，再按本文配置邮件。

SMTP 参数在后台保存，下一次发送就会使用新配置，无需重启容器。当前版本不读取 `SMTP_HOST`、`SMTP_PASSWORD` 等环境变量，不需要把邮箱账号或授权码写进 `docker-compose.yml`。

## 1. 先区分发件账户、收件邮箱和后台密码

| 项目 | 用途 | 在哪里填写 |
| --- | --- | --- |
| 发件账户 | 网站借助这个账户的 SMTP 服务发送邮件，全站共用一套配置 | “邮件设置”中的 SMTP 用户名、密码及发件邮箱 |
| 收件邮箱 | 接收重置通知，可添加多个地址 | “收件邮箱”；只填地址和可选备注，不需要收件人密码 |
| 后台管理员密码 | 登录本站 `/admin` | 后台登录页；与邮箱授权码无关 |

发件邮箱和收件邮箱可以相同，也可以属于不同服务商。例如使用 QQ 邮箱发信，同时通知自己的 QQ、163 或工作邮箱。只配置收件地址还不能发信，需要同时配置发件账户的 SMTP 服务。

读取自动生成的后台密码：

```sh
# 在服务器的 Compose 部署目录执行
cd "$HOME/codex-reset" || exit 1
docker compose exec reset cat /app/data/admin-password.txt
```

如果部署时自行设置了 `ADMIN_PASSWORD`，使用自己设置的值。

## 2. 按顺序完成首次配置

1. 打开 `http://服务器IP:3000/admin`，或自己的 HTTPS 域名下的 `/admin`，登录后台。
2. 在“收件邮箱”填写接收地址，可填“工作邮箱”等备注，然后点击“添加邮箱”。新添加的地址默认启用；确认列表显示“已启用”。
3. 打开“邮件设置”，按照下一节填写 SMTP 参数。首次配置时先保持“启用重置邮件通知”未勾选，点击“保存邮件设置”。
4. 回到“收件邮箱”，在“发送测试邮件”区域选择一个已启用地址，点击“发送一封测试邮件”。发送使用已保存的参数，未保存的表单编辑不会生效。
5. 看到“SMTP 已接受”后，实际检查该邮箱的收件箱和垃圾箱，确认收到主题为 `[Codex Reset] 邮件提醒测试` 的邮件。这个状态只表示 SMTP 服务接受了邮件，不能证明收件箱最终收到。
6. 确认收件后，回到“邮件设置”，勾选“启用重置邮件通知”，再次点击“保存邮件设置”。
7. 在“数据同步”确认“启用定时同步”已勾选，保留默认 5 分钟间隔或按需调整，点击“保存同步设置”。检查最近成功同步时间；第一次导入已完成的历史不会群发，当前新发现的有效预告可发送一次提醒。
8. 后续新重置的通知结果在“发送日志”查看，点击“刷新日志”更新状态。

测试邮件不受自动提醒开关控制，但收件邮箱必须启用。两次测试请求至少间隔 10 秒；测试失败后修正设置，再手动测试。测试邮件不进入自动投递队列，也不会显示在“发送日志”列表，只显示在“收件邮箱”页的“最近测试”中。

## 3. “邮件设置”每个字段怎么填

| 后台字段 | 填写方法 | 常见错误 |
| --- | --- | --- |
| SMTP 主机 | 服务商提供的发信主机名，例如 `smtp.qq.com` | 不要填邮箱地址、`https://`、`smtp://`、端口或网页路径 |
| SMTP 端口 | 填整数，常见为 `465` 或 `587`，与加密方式配套 | 端口应填在这里，不要拼进主机名 |
| SMTP 用户名 | QQ、163、Gmail 填完整发件邮箱；其他服务按供应商提供的 SMTP 登录名填写 | 不要把收件人的账号填进来 |
| SMTP 密码 / 授权码 | 填发件账户生成的 SMTP 授权码或应用专用密码 | QQ、163 的授权码不是邮箱网页登录密码；不要粘贴额外空格或换行 |
| 发件邮箱 | 邮件中展示的 From 地址；首次配置填与 SMTP 登录账户相同的完整邮箱 | 使用其他地址或别名，需要服务商明确允许该账户以此地址发信 |
| 发件人名称 | 收件人看到的显示名称，可填 `Codex Reset`；最长 60 个字符 | 它是名称，不是邮箱地址 |
| 使用隐式 TLS | 465 端口通常勾选；587 端口通常不勾选，见下表 | 端口和复选框不匹配可能造成 TLS 错误或超时 |
| 清除已保存的 SMTP 密码 | 仅在明确要删除已保存凭据时勾选 | 更换授权码时不要同时勾选，否则新填的密码也会被清除 |
| 启用重置邮件通知 | 同时控制预告和正式重置提醒；先测试成功，再勾选并保存 | 只勾选但不保存不会生效 |

密码保存后不回显，输入框为空且旁边显示“已保存”是正常现象。留空并保存会保留原密码；输入新值并保存会替换原密码。要确认新配置，重新发送一封测试邮件。

### 465 与 587 的对应关系

| 服务商要求 | 本站端口 | “使用隐式 TLS” | 实际连接方式 |
| --- | --- | --- | --- |
| SSL/TLS、SMTPS、隐式 TLS | `465` | 勾选 | 一开始就建立 TLS 加密连接 |
| STARTTLS | `587` | 不勾选 | 先建立 SMTP 连接，再强制升级为 TLS |

不勾选隐式 TLS 仍然要求加密：本站不会退回明文发信，且会校验证书。端口以供应商配置为准，不要把所有服务商都统一改成同一个端口。“使用隐式 TLS”只控制 SMTP 连接，与网站自身的 HTTP/HTTPS、`SECURE_COOKIE` 是分别配置的。

当前版本支持 SMTP 用户名加密码或授权码认证，未实现 OAuth2 登录。若某个账户仅允许 OAuth2，需改用服务商支持的 SMTP 应用凭据或合适的 SMTP 服务；把 OAuth token 填进密码框不能实现 OAuth2。

## 4. 常见发件账户示例

以下都是填写模板，必须换成自己的账号和授权码。服务商可能调整界面或账号政策，以实际账户设置为准。

### QQ 邮箱

在 QQ 邮箱网页版，进入“设置”→“账号与安全”→“安全设置”，开启相关客户端协议服务，再生成授权码并完成身份验证。把得到的授权码用于本站 SMTP 密码栏。更改 QQ 账号密码后，原授权码可能需要重新生成。具体流程见 [QQ 邮箱官方授权码说明](https://help.mail.qq.com/detail/106/985)。

| 字段 | 填写值 |
| --- | --- |
| SMTP 主机 | `smtp.qq.com` |
| SMTP 端口 | `465` |
| SMTP 用户名 | 自己的完整 QQ 邮箱，例如 `你的QQ号@qq.com` |
| SMTP 密码 / 授权码 | 刚生成的授权码 |
| 发件邮箱 | 与 SMTP 用户名相同的邮箱 |
| 发件人名称 | `Codex Reset` |
| 使用隐式 TLS | 勾选 |

主机与端口参考 [腾讯云 QQ 邮箱 SMTP 配置表](https://main.qcloudimg.com/raw/document/product/pdf/1270_46586_cn.pdf#page=33)。

### 网易 163 个人邮箱

登录网易邮箱网页版，在设置中进入 POP3/SMTP/IMAP 相关选项，开启包含 SMTP 的客户端服务，完成验证后获取客户端授权码。填写以下参数。该流程及端口可参照 [腾讯云官方文档中的 163 邮箱配置示例](https://ioa.cloud.tencent.com/support/199262718652653568/)。

| 字段 | 填写值 |
| --- | --- |
| SMTP 主机 | `smtp.163.com` |
| SMTP 端口 | `465` |
| SMTP 用户名 | 自己的完整 `@163.com` 邮箱 |
| SMTP 密码 / 授权码 | 网易邮箱生成的客户端授权码 |
| 发件邮箱 | 与 SMTP 用户名相同的邮箱 |
| 发件人名称 | `Codex Reset` |
| 使用隐式 TLS | 勾选 |

这组参数针对个人 163 邮箱；企业邮箱应使用管理员或服务商给出的企业 SMTP 参数。

### Gmail / 支持应用专用密码的 Google 账户

先开启 Google 账户两步验证，再为本应用生成应用专用密码。学校、工作账户、仅使用安全密钥的账户或高级保护账户，可能没有这个选项；应按管理员或 Google 的规则确认是否可用。修改 Google 账户密码后，应用专用密码会被撤销，需要更新本站配置。参见 [Google 应用专用密码说明](https://support.google.com/accounts/answer/185833?hl=zh-Hans)。

| 字段 | 填写值 |
| --- | --- |
| SMTP 主机 | `smtp.gmail.com` |
| SMTP 端口 | `587` |
| SMTP 用户名 | 完整的 Gmail 或允许使用该 SMTP 服务的 Google Workspace 邮箱 |
| SMTP 密码 / 授权码 | 为本应用生成的应用专用密码 |
| 发件邮箱 | 与 SMTP 用户名相同的邮箱 |
| 发件人名称 | `Codex Reset` |
| 使用隐式 TLS | 不勾选，使用 STARTTLS |

如选择 `465`，需同时勾选隐式 TLS。参数依据 [Google 官方 Gmail SMTP 配置](https://knowledge.workspace.google.com/admin/gmail/send-email-from-a-printer-scanner-or-app) 中的 Gmail SMTP server 方案；服务器必须能连接该主机，账户也必须允许所选认证方式。

## 5. 自动提醒什么时候会发送

自动提醒需要同时满足：至少一个已启用收件邮箱、可用的 SMTP 配置、已保存的“启用重置邮件通知”开关，以及后续发现的新预告或正式重置。自动发现还要求“数据同步”中的定时同步开启；默认每 5 分钟检查数据源，发送队列约每 15 秒处理一次。

- 第一次完整同步用于建立已完成重置的历史基线，不会给历史记录群发邮件；当前新发现的有效预告可发送一次。升级前只有展示、从未生成投递任务的当前预告，在升级后首次读取时也可提醒一次。
- 新预告邮件标题包含“重置预告”，正文注明尚未确认完成、预计时间（北京时间）和原帖链接；没有明确预计时间时显示“尚未公布”。
- 数据源确认正式重置后，再发送一封正式提醒。即使它沿用预告的 ID、链接或公告时间，也会作为另一个阶段处理。仅到达预计时间不会触发正式提醒。
- 已有记录重复同步、较早补录的历史、只新增收件地址或只打开提醒开关，都不会补发已经收录的阶段。修改同一条预告的时间或原文不会额外发信。
- 历史接口临时故障时，仍可通过状态接口发送预告和最新正式提醒；后台会保留同步错误。历史恢复后相同记录不会重发，尚未完成首次历史导入时也不会群发旧记录。
- 正式重置、预告撤下或被替代后，取消该预告尚未发送或待重试的邮件，避免正式提醒之后再发送过期预告。
- 手动录入真实原帖时，需要同时勾选“收录后向已启用邮箱发送通知”，并已开启全局邮件通知。不要为了测试发信而向公开历史中添加虚构重置，使用“发送测试邮件”即可。
- 每个“来源记录 + 通知阶段（预告／正式）+ 收件邮箱”最多创建一个任务，记录持久化在 SQLite 中；重复轮询、程序重启和容器重建不会清除去重记录。逐个收件人发送，其他订阅地址不会暴露给收件人。
- 关闭全局提醒或停用收件人会暂停相应待处理任务；重新开启后，尚未完成且未超过重试上限的任务会继续。

明确失败的投递（例如连接建立失败、SMTP 明确拒收）按 1、2、4、8 分钟退避，最多尝试 5 次；实际执行还受调度间隔影响。达到上限后停止自动重试。当前后台没有对单条失败任务“立即重试”的按钮，修正 SMTP 设置或重启服务不会重置已达到上限的次数；应先用测试邮件确认修复，后续新预告和正式重置会使用新配置。

“发送日志”会分别标注“重置预告”和“正式重置”，状态包括“等待发送”“发送中”“SMTP 已接受”“投递失败”“结果待确认”和“已取消”；可同时查看尝试次数和错误信息。归档重置会取消它尚未发送的通知。

SMTP 无法在回执丢失时同时保证必达和绝不重复。新版优先避免重复：发送中进程退出，或 SMTP 连接中断而无法确定邮件是否已接受时，任务标为“结果待确认”，不自动重发；请核对收件箱、垃圾箱或服务商日志。这可能留下未送达的邮件，但不会靠自动重试冒险再发一封。程序仍为每个投递任务使用稳定的 Message-ID；不同通知阶段使用不同 ID。

## 6. 常见问题排查

先看发送测试时的页面提示，或“发送日志”中的自动投递错误；刷新后台后可查看“收件邮箱”中的最近测试结果。应用会保存经过处理的错误信息，不回显 SMTP 密码。

| 提示或现象 | 检查与处理 |
| --- | --- |
| 请先保存 SMTP 主机与发件邮箱 | 补齐两项后点击“保存邮件设置”，再返回收件邮箱页测试 |
| 请选择一个启用的收件邮箱 / 无法选择测试对象 | 添加收件地址并确认“已启用”，在下拉框选择它 |
| SMTP 登录失败，请检查用户名与授权码 | 检查完整发件账号、授权码、客户端 SMTP 服务是否开启；更换或撤销过密码时生成新授权码并保存 |
| 无法连接 SMTP 服务器 / SMTP 连接超时 | 检查主机、DNS、端口及服务器出站规则；某些云平台或网络可能限制 SMTP 连接 |
| SMTP TLS 或连接异常 | 对照端口与隐式 TLS 复选框；检查系统时间、服务端证书和证书主机名，修复问题而不是关闭证书验证 |
| SMTP 拒绝发件人或收件人 | 发件邮箱先使用认证账户自己的地址；确认收件地址有效，账号允许给该地址发信 |
| SMTP 拒绝邮件内容 / 未获服务器确认 | 检查服务商的发送限制、风控或退信信息，处理后手动测试 |
| 请等待 10 秒后再发送测试 | 距离上一次测试请求满 10 秒后再试，避免连续点击 |
| SMTP 已接受，但没收到 | 检查垃圾箱、隔离区、收件规则、地址拼写和稍后收到的退信；“已接受”不是最终送达回执 |
| 测试邮件正常，自动提醒没有发送 | 检查全局开关、收件人状态、自动同步及最近成功时间；确认实际出现了基线之后的新记录，并在发送日志点击刷新 |
| 密码框保存后仍是空的 | 查看旁边是否显示“已保存”；程序故意不返回密码，留空保存会保留原值 |
| 保存提示“请求来源无效”或会话错误 | 核对浏览器地址与 `APP_URL`、反向代理协议配置，刷新并重新登录；这类问题发生在保存之前，与 SMTP 认证不同 |

### 网络和端口

程序主动连接外部 SMTP 服务，需要允许服务器出站访问所用 SMTP 主机与端口。Compose 的 `ports` 只映射网站的 3000 端口；使用第三方 SMTP 发信不需要给本容器添加 `465:465` 或 `587:587` 映射，也不需要为此开放服务器的 SMTP 入站端口。

若 SMTP 主机填写 `localhost` 或 `127.0.0.1`，在容器中指的是应用容器本身。只有确实在同一容器内提供 SMTP 服务时才这样填；第三方邮箱使用服务商给出的域名。

在安装了 OpenSSL 和 `timeout` 命令的 Linux 服务器上，可进行以下连接检查，不包含账号、密码或邮件内容：

```sh
# QQ 邮箱 465：隐式 TLS
timeout 15 openssl s_client -connect smtp.qq.com:465 -servername smtp.qq.com -verify_hostname smtp.qq.com -verify_return_error -brief </dev/null

# Gmail 587：STARTTLS
timeout 15 openssl s_client -starttls smtp -connect smtp.gmail.com:587 -servername smtp.gmail.com -verify_hostname smtp.gmail.com -verify_return_error -brief </dev/null
```

这只验证宿主机到 SMTP 的连接和 TLS；最终仍需通过后台测试，验证容器网络、账户认证和真实收件。连接超时优先排查网络；认证失败优先排查账号授权。应用运行日志可在部署目录查看：

```sh
docker compose logs --tail 100 reset
```

## 7. 配置保存、更新与备份

使用当前目录挂载配置时，服务器 `/data/codex-reset` 对应容器内 `/app/data`：

| 文件 | 作用 |
| --- | --- |
| `reset.sqlite` 及可能存在的 WAL 相关文件 | 收件人、邮件配置、历史记录、投递状态；SMTP 密码加密后保存 |
| `secret.key` | 解密已保存 SMTP 密码所需的密钥，必须与数据库一起保留 |
| `admin-password.txt` | 未配置 `ADMIN_PASSWORD` 时生成的后台登录密码，不是 SMTP 授权码 |

后台修改邮箱配置并保存即可生效。更新授权码时，在密码框输入新值、保持“清除已保存的 SMTP 密码”未勾选、保存并再次测试。不要把实际凭据放进 README、Compose、Git 提交或排障截图。

`docker compose down` 不会删除绑定的服务器目录。迁移或备份时，先停止应用，再完整复制目录并保留文件权限；只保留数据库而丢失 `secret.key` 会导致原 SMTP 密码无法解密。部署、迁移和运维命令见 [README](../README.md)。
