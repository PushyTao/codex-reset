# Codex Reset 设计

## 目标
中文 Codex 重置公告网站，参考 quota-reset.com 的米白、黑色粗体、绿色状态和日历布局。首页没有后台入口；管理员通过 `/admin` 登录，维护重置记录、收件邮箱、SMTP 与采集设置。

## 架构
自托管 Node.js 24，Express 提供页面与 API，SQLite 持久化。静态 HTML/CSS/JS 不需要前端构建。单进程调度采集和邮件队列，Docker 单副本部署，数据卷保存数据库与本地密钥。HTTPS 由反向代理终止。

## 前台
最新公告、距离上次重置时间、下一次公告状态、近 90 天统计与逐日日历、公告列表与分类、时间区域切换、数据新鲜度。所有统计来自已发布记录；不编造下一次时间或用户的个人剩余额度。普通重置与备用额度分开展示。原文链接回 X。

## 后台与数据
登录会话使用 HttpOnly / SameSite Cookie，HTTPS 环境 Secure；密码使用 scrypt 派生，登录限速，写接口校验同源和 CSRF。初始密码由服务器环境变量指定，或随机生成保存到服务端文件，不提供公共远程初始化。私密设置与日志仅登录可见，SMTP 密码使用本地密钥加密，读取时掩码。可添加、停用邮箱；创建、发布、归档记录；保存 SMTP；向管理员选定收件人发送测试；查看投递结果。

## 采集
按用户补充，唯一自动数据源为 Codex Resets 免费公开 API。`/api/v1/resets` 分页提供历史，`/api/v1/status` 提供待执行预告。不需要 X Token。默认每 5 分钟同步；首次拉取只建立历史基线，不群发历史。按来源 ID 去重，分页失败不提交本批次。保留 `observed` 社区观测与 `x_post` 原帖的归属区别。待执行预告不计入完成记录，不触发已重置提醒。显示来源链接与同步新鲜度。后台保留手动录入 Tibo 原帖。

## 邮件
发布新记录时，为当前启用的邮箱生成唯一 `(event_id, recipient_id)` 投递项。SMTP 按收件人单独发送，不泄露其他地址。失败有限退避重试；SMTP 接受后进程崩溃存在至少一次投递语义，文档明确边界。测试邮件需明确点击，测试环境使用本地 SMTP，不触达真实邮箱。删除邮箱使用停用/归档，保留审计日志。

## 验证
Node test runner 验证鉴权、同源保护、凭据掩码、持久化、URL/邮箱校验、来源类型/去重、基线导入不群发、投递去重与失败重试。浏览器检查首页、后台登录、保存收件人和移动端布局。SMTP 用本地协议测试服务器验证实际邮件内容。
